أكمل الفجوات المتبقية بلوحة تحكم مسك اللولو (ضمن خطة المهمة الأصلية للوحة التحكم الكاملة):

## 1. تفاصيل الطلب الكاملة

حاليًا نافذة/صفحة تفاصيل الطلب بالأدمن تعتمد على بيانات الصف بجدول الطلبات فقط، بدون endpoint مستقل يجيب التفاصيل الكاملة. أضف:

- Endpoint: GET /admin/orders/:id (لو غير موجود فعليًا بشكل كامل) يرجع:
  - بيانات الطلب الأساسية (رقم الطلب، الحالة، حالة الدفع، رقم التتبع، التواريخ)
  - بيانات العميل المرتبط بالطلب (الاسم، رقم الجوال، البريد إن وُجد) عبر join مع storefront_customers
  - عنوان الشحن الكامل من storefront_order_addresses (نسخة وقت الطلب، مو عنوان العميل الحالي)
  - قائمة كاملة بعناصر الطلب (المنتجات المطلوبة) من storefront_order_items: اسم المنتج، الكمية، السعر وقت الطلب، الإجمالي الفرعي
  - ملخص مالي: subtotal, discount, tax, shipping_cost, total
  - الكوبون المستخدم إن وُجد (الكود ونسبة/قيمة الخصم)

- عدّل واجهة تفاصيل الطلب بالأدمن لتستدعي هذا الـ endpoint المستقل وتعرض كل هذي البيانات بشكل منظم (قسم لبيانات العميل، قسم للعنوان، جدول لعناصر الطلب، قسم للملخص المالي)

## 2. نظام سجل حركات المخزون (Inventory Movement Log)

حاليًا المخزون مجرد رقم كمية بجدول المنتجات (stock_quantity) بدون أي تتبع تاريخي. أضف:

- جدول جديد بالـ schema: inventory_movements
  - id, product_id (FK), movement_type (enum: 'increase' | 'decrease' | 'adjustment'), quantity_change (integer, يمكن يكون سالب أو موجب), quantity_before, quantity_after, reason (text, اختياري - مثل "إعادة تعبئة" أو "طلب عميل" أو "تصحيح جرد"), performed_by (FK إلى admin_users.id), created_at

- عند كل عملية تُغيّر stock_quantity لمنتج (سواء من شاشة المخزون مباشرة، أو تلقائيًا عند إنشاء طلب جديد ينقص الكمية)، سجّل حركة جديدة بجدول inventory_movements تلقائيًا

- Endpoint جديد: GET /admin/inventory/:productId/movements يرجع سجل الحركات الكامل لمنتج معين مرتب من الأحدث للأقدم، محمي بصلاحية inventory:view

- Endpoint جديد: POST /admin/inventory/:productId/adjust يسمح للموظف (بصلاحية inventory:edit) بتعديل الكمية يدويًا مع سبب إلزامي (reason)، ويسجّل الحركة تلقائيًا مع performed_by = المستخدم الحالي

- عدّل واجهة المخزون بالأدمن: أضف زر "عرض السجل" لكل منتج يفتح قائمة الحركات التاريخية، وزر "تعديل الكمية" يفتح نموذج بسيط (الكمية الجديدة + السبب) بدل التعديل المباشر الحالي بدون سبب

## بعد التنفيذ

طبّق الـ schema الجديد (pnpm --filter @workspace/db run push)، اكتب اختبارات تتحقق من:
- نجاح جلب تفاصيل طلب كاملة مع كل عناصره
- تسجيل حركة مخزون تلقائيًا عند تعديل الكمية يدويًا
- رفض تعديل مخزون بدون صلاحية inventory:edit

شغّل pnpm run typecheck وتأكد من نجاحه، واعطني ملخص شامل بالملفات المعدّلة والجداول الجديدة ونتائج الاختبارات.
