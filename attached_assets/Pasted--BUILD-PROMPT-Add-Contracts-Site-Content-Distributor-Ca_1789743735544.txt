### Frontend
- Admin pages only: contract list (table with status badges), create/edit form, view page, print-friendly view
- A signature-capture component (canvas-based, e.g. `react-signature-canvas`) reusable for both seller and buyer signing
- Only if building online buyer-signing: one new, isolated public page at `/contracts/sign/:token` where the buyer reviews the contract and signs — this is a new route only, no existing file is touched
- PDF generation should render the contract bilingually (Arabic RTL layout) with a QR code linking to the verification/download URL — use `pdfkit` + `qrcode` + an Arabic text-shaping library (`arabic-reshaper` or equivalent) if this project doesn't already have an Arabic-PDF solution

### Business flow
1. Admin creates contract (draft) → 2. Admin (seller) signs → 3. Admin clicks "send" → either a signing link is generated and sent to the buyer (online path), or the admin exports the PDF to send manually (offline path) → 4. Buyer signs → 5. Contract becomes final; a separately-tokened PDF download link is available for the online path, or the admin uploads the signed-back copy for the offline path.
